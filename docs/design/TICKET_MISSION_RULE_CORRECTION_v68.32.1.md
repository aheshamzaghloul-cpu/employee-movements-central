# v68.32.1 — تصحيح شرط إنشاء المأمورية من صورة التيكيت

## القاعدة المعتمدة

تُنشأ المأمورية فقط إذا كانت الإجابتان معًا:

- **هل الفرع المحول إليه فرعك الأساسي؟** = **لا، ليس فرعي الأساسي** (`destination_is_basic = no`).
- **هل تحتاج مأمورية؟** = **نعم** (`needs_mission = yes`).

أي تركيبة أخرى تمنع الإنشاء برسالة صريحة.

## فحوص الفرع والموظف

- مطابقة الكود الوظيفي لموظف نشط وفريد ومسموح للمستخدم بإدارة حركته.
- مطابقة اسم الفرع الأساسي في الصورة مع فرع الموظف في قاعدة البيانات (مع تطبيع فروق الكتابة والمسافات وعلامات الترقيم).
- منع اختيار نفس معرّف الفرع الأساسي كوجهة عندما تكون الإجابة «لا، ليس فرعي الأساسي».
- لا يُختار الفرع آليًا من OCR إلا عند العثور على مطابقة وحيدة ضمن الفروع النشطة المسموح بها؛ الاسم المكرر أو غير الواضح يطلب اختيارًا يدويًا.

## OCR والتواريخ

- دُعمت الإجابة الطويلة «لا ليس فرعي الأساسي» وما قد يقرأه OCR من خطأ مطبعي محدود في خيار نعم/لا.
- حُسنت حدود الأعمدة وترتيب النص من اليمين إلى اليسار، مع إبقاء كود الموظف بترتيبه الرقمي.
- عند تجربة صورة المستخدم الفعلية بعد التصحيح، استُخرجت الحقول السبعة. ما زال نص وجهة التحويل يحتوي بعض تشويش OCR، ولذلك لا يعتمد التطبيق عليه وحده إذا لم تطابق وجهة واحدة مسموحًا بها.
- تقرأ حقول «من يوم» و«إلى يوم» التاريخ، ولا تعتمد على تطابق الساعة. اليوم نفسه صالح لمأمورية يوم واحد. يُرفض التاريخ غير الصحيح أو النهاية السابقة للبداية أو التعارض مع حركة أخرى.

## الاختبارات التي نُفذت

- **3/3 اختبارات موجهة** لقواعد القرار الأربع، استخدام القاعدة داخل مسار الحفظ، والتحقق من نص الواجهة.
- **2/2 اختبارات OCR/التاريخ**، بما فيها قراءة «لا» مع بقية العبارة وتاريخي البداية والنهاية في اليوم نفسه.
- **4 تأكيدات تطبيع** لقيم نعم/لا على OCR، بما فيها «لا ليس فرعي الأساسي» والصيغ المقروءة المشوشة.
- اجتازت ملفات Python التجميع، وقوالب Jinja2 وعددها 46 التحليل، وملفات CSS الستة وملفات JavaScript الثمانية فحص الصياغة.

## حدود الاختبار

تعذّر تشغيل تطبيق Flask واختبارات قاعدة البيانات المتكاملة لأن Flask غير مثبت في بيئة المراجعة؛ لذلك هذه فحوص قاعدة القرار وOCR والمصدر وليست اختبار حفظ حي. لم يتم النشر ولم تُعدّل قاعدة بيانات الإنتاج.
