# تقرير إصلاحات المشرف وتسجيل الحركة والمدخلين الأوائل وبسيوني — v68.28.0

## التغييرات

1. **نطاق مشرف المحافظة:** يتم اختيار المحافظة تلقائيًا فقط عندما يكون للمشرف نطاق نشط واحد. عند تعدد المحافظات أو التفويضات يبقى الاختيار مطلوبًا. لا يجري اختيار محافظة افتراضية لمسؤول التطبيق أو Manager. كما يعاد التحقق من أن المحافظة المخزنة في الجلسة لا تزال ضمن النطاق النشط للمستخدم.
2. **تسجيل الحركة:** يتم تعيين محافظة محددة إلى محدد التسجيل إذا كانت محافظة العمل محددة، وتحميل الفروع من البداية. تغيير نوع الحركة يعيد تحميل الفروع للمحدد الصحيح. يرفض المتصفح استجابات API غير الناجحة ويعرض رسالة واضحة بدل ألا يحدث شيء.
3. **«اختيار موظف» في الرئيسية:** يمرر الزر المستخدم إلى قسم البحث ويضع التركيز في خانة الاسم/الكود. يظل الرابط صالحًا عند تعطيل JavaScript.
4. **المدخلون الأوائل:** أصبحت كل بطاقة فرع قابلة للفتح. تعرض القائمة المتوسعة الموظفين النشطين بالاسم والكود والمسمى الوظيفي، ويرتبط كل منهم بملفه داخل التطبيق. البيانات المستخدمة هي مجموعات الفروع والموظفين التي يحسبها الخادم ضمن نطاق الصفحة.
5. **تعلم الأسماء:** يتعامل البحث مع الاختلافات العربية الشائعة، ومنها `أحمد` و`احمد`، عبر تطبيع SQL يتوافق مع SQLite وPostgreSQL. يدعم بسيوني تعلّم اسم بديل لموظف معروف من عبارة مثل «أحمد هو حمادة» عندما يمكن حسم الطرفين إلى سجل واحد؛ يخزن الربط خاصًا بحساب المستخدم، ولا يستبدل ربطًا متعارضًا بصمت. إذا كانت العبارة مجرد اختلاف إملائي متكافئ، فيُعالجها تطبيع البحث دون ربطها اعتباطيًا بسجل واحد.
6. **الخصوصية:** يتم التعامل مع عبارة التعلم محليًا قبل استدعاء وكيل المحادثة. تُضاف الأسماء المستعارة المحفوظة إلى فحص الخصوصية المحلي لكي تُحجب عند ظهورها في النصوص المهيأة للنموذج الخارجي.
