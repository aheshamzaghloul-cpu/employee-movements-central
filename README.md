# نظام إدارة حركات الموظفين المركزي — Cyan

مشروع Flask عربي باتجاه RTL وتصميم موحّد بدرجات السيان وخط Cairo. يتضمن أساسًا لتسجيل الدخول، وأدوار المستخدمين، واختيار محافظة العمل، والبحث المركزي عن الموظفين، وإدارة أولية للموظفين والمحافظات والفروع، والحركات والتقارير والتفويضات.

> هذه نسخة تأسيسية متقدمة وليست حتى الآن بديلًا مكتملًا ومختبرًا لكل وظائف النظام القديم. لا تنقل إليها بيانات الإنتاج ولا تستبدل النظام القديم قبل إكمال اختبارات القبول والوظائف الموضحة أدناه.

## نقطة البداية المعتمدة

- يبدأ التطبيق بقاعدة بيانات جديدة وفارغة؛ لا يستورد المحافظات أو الفروع أو أي بيانات من النظام القديم.
- اسم الدور الإداري الظاهر للمستخدم هو **Admin**.
- اسم الدخول الافتراضي المقترح لحساب البداية هو `admin`، لكن يجب تعيين كلمة مرور قوية عبر `BOOTSTRAP_ADMIN_PASSWORD` في أسرار بيئة التشغيل. لا توجد كلمة مرور ثابتة داخل المشروع.
- هذه حزمة تأسيسية وليست بديلًا مكتملًا أو جاهزًا لاستبدال تطبيق الإنتاج. رقم الإصدار الحالي: 1.0.5.

## التشغيل محليًا

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
```

اضبط متغيرات البيئة محليًا قبل التشغيل. أنشئ `SECRET_KEY` عشوائيًا، وحدد `BOOTSTRAP_ADMIN_USERNAME` و`BOOTSTRAP_ADMIN_PASSWORD` (12 حرفًا على الأقل)، ثم شغّل:

```bash
python app.py
```

افتح `http://127.0.0.1:5000`.

## إعداد النشر

- استخدم PostgreSQL واضبط `DATABASE_URL`. في بيئة الإنتاج يرفض التطبيق البدء دون `DATABASE_URL` و`SECRET_KEY` عشوائي بطول 32 حرفًا على الأقل.
- اضبط `APP_ENV=production` لتفعيل خصائص ملفات تعريف الارتباط الآمنة.
- أنشئ المسؤول الأول باستخدام `BOOTSTRAP_ADMIN_USERNAME` و`BOOTSTRAP_ADMIN_PASSWORD`. لا تضع كلمات المرور أو مفاتيح الخدمة في GitHub.
- أمر التشغيل: `gunicorn app:app --workers 2 --bind 0.0.0.0:$PORT --access-logfile - --error-logfile -`.

## حساب المراجعة المؤقت `full_review_test`

إنشاء الحساب اختياري ومغلق افتراضيًا. لتفعيله أثناء فترة المراجعة، اضبط القيم التالية في أسرار بيئة النشر فقط:

- `REVIEW_ACCOUNT_ENABLED=1`
- `REVIEW_USERNAME=full_review_test`
- `REVIEW_PASSWORD` = كلمة مرور عشوائية وفريدة بطول 16 حرفًا على الأقل

عند بدء التطبيق يُنشأ الحساب إذا لم يكن موجودًا، ويُمنح دور Admin لمراجعة جميع الصفحات والوظائف الإدارية المتاحة. إذا كان الاسم مستخدمًا من حساب عادي، يتوقف بدء التطبيق برسالة واضحة بدلًا من ترقية الحساب خطأً. عند ضبط `REVIEW_ACCOUNT_ENABLED=0`، يُعطّل حساب المراجعة الموجود دون حذفه. لا تستخدم الحساب في التشغيل اليومي، ولا تستخدمه مع بيانات حقيقية إلا عند الضرورة وبموافقة مناسبة. بعد انتهاء المراجعة، عطّل الحساب ودوّر أسرار الوصول.

## الحماية المضافة في هذه النسخة

- حماية CSRF للنماذج وطلب المساعد AJAX.
- رفض عنوان `next` الخارجي بعد تسجيل الدخول لتجنب إعادة التوجيه المفتوح.
- رفض تشغيل الإنتاج بسرّ جلسة افتراضي أو دون قاعدة بيانات محددة أو دون حساب Admin نشط.
- ضبط Secure Cookie حسب وضع APP_ENV الفعلي، حتى لا تتعطل جلسة تسجيل الدخول عند التشغيل المحلي على HTTP.
- كلمات مرور مخزنة باستخدام `werkzeug` password hashing، وحساب المراجعة لا يُنشأ إلا بإعداد صريح.

## ما يزال مطلوبًا قبل استبدال النظام القديم

- استيراد وتصدير Excel للمحافظات والفروع والموظفين.
- إدارة تكليفات المدخل الأول المرتبطة بسجلات الموظفين والفروع.
- استكمال إدارة صلاحيات ونطاقات العمل والتفويضات من مركز الإدارة بصورة كاملة.
- اختبار واجهة تعديل المستخدم وتغيير الدور وإعادة تعيين كلمة المرور، مع حماية آخر حساب Admin نشط.
- دورة انتهاء الانتداب والتنبيه والمراجعة والتمديد وإصدار نموذج مأمورية قابل للطباعة.
- سجل تدقيق شامل وتغطية اختبارات للصلاحيات والأمان والوظائف.
- ربط Gemini ببيانات النظام مع تحليل موثوق وتنفيذ إجراءات بعد تأكيد المستخدم والتحقق من الصلاحيات على الخادم.

المساعد في هذه النسخة لا ينفّذ تغييرات على قاعدة البيانات. يجب اختبار كل دور ومسار قبل استخدام بيانات الإنتاج.
