# Employee Movements Central

**إصدار التطبيق:** `69.00.5`  
**حزمة المصدر الكاملة:** الجولة 35 — مرشح مراجعة قبل الرفع، غير معتمد للإنتاج.

## ما الذي تحتويه هذه الحزمة؟

هذه هي حزمة المستودع الكاملة المناسبة للرفع إلى GitHub وربطه ببيئة الاستضافة. وهي تتضمن:

- تطبيق Flask كاملًا داخل `employee_movements/` مع القوالب وملفات CSS/JavaScript والأصول.
- نقاط الدخول `app.py` و`wsgi.py`، وملفات Docker/Compose وGunicorn.
- `requirements.txt` للتشغيل و`requirements-dev.txt` للتطوير والتحقق.
- مجموعتي `tests/` و`contract_tests/`، وأدوات `scripts/`، وسير عمل CI في `.github/workflows/ci.yml`.
- الوثائق التشغيلية والمعمارية الأساسية داخل `docs/`، وبيانات الإصدار الحالية.

أُزيلت تقارير المراجعة الخاصة بالجولات القديمة من جذر المستودع لتقليل التشويش، وحُفظت في أرشيف تاريخي منفصل. لم تُحذف وحدات التطبيق أو الاختبارات أو أدوات الصيانة المطلوبة للمستودع.

## الرفع إلى GitHub / Blitz

1. فك ضغط هذا الملف محليًا.
2. ارفع **محتويات المجلد المستخرج** إلى جذر مستودع GitHub، وليس ملف ZIP وحده.
3. احرص على تضمين الملفات المخفية مثل `.github/` و`.gitignore` و`.dockerignore` و`.env.example`.
4. إذا كان المستودع الحالي يحتوي على `.git/`، فلا تستبدله ولا ترفع مجلد `.git` من نسخة أخرى؛ حدّث ملفات المشروع داخل المستودع الحالي.
5. لا ترفع ملف `.env` الفعلي أو كلمات المرور أو مفاتيح Gemini أو قواعد بيانات محلية. استخدم إعدادات الأسرار في منصة الاستضافة.
6. راجع `docs/BLITZ_DEPLOYMENT_AR.md` و`RELEASE_RUNBOOK_v69.00.5_AR.md` قبل أي نشر.

## التشغيل المحلي والتطوير

- يتطلب المشروع Python 3.12 أو أحدث وفق `pyproject.toml`.
- متطلبات التشغيل في `requirements.txt`، ومتطلبات التطوير والاختبارات في `requirements-dev.txt`.
- يحتوي `.env.example` على أسماء الإعدادات فقط؛ أنشئ إعدادات البيئة الفعلية خارج Git.
- يوفر `.github/workflows/ci.yml` مسار CI للتحقق من الاعتماديات والاختبارات والتكامل مع PostgreSQL وصورة Docker. لم يُشغّل هذا المسار ضمن هذه المراجعة.

## ما الذي تغيّر في الجولة 35؟

- تحديث Pillow إلى `13.0.0` بعد إصلاحات أمنية إضافية في الإصدار الرسمي، مع التحقق ساكنًا من عدم استخدام واجهات Pillow التي أزيلت في الإصدار الجديد.
- قصر فتح صور التيكيت ومرفقات المأموريات على صيغ الصور المعتمدة (PNG/JPEG/WEBP) عند مرحلة فك الترميز، إلى جانب حدود الحجم والأبعاد والتحقق من سلامة الملف.
- إضافة عقد مصدر لحماية سياسة صيغ الصور، وجعل عقود الإصدار تقرأ رقم الجولة الحالي من البيان بدل تثبيته على جولة قديمة.
- تحديث بيانات الإصدار إلى `69.00.5` والجولة 35؛ والاحتفاظ بمستندات الجولة 34 في أرشيف تاريخي منفصل.
- فحوص مصدرية ساكنة فقط؛ لم تُشغّل اختبارات pytest أو التطبيق أو قاعدة البيانات أو `pip install` أو Docker.
